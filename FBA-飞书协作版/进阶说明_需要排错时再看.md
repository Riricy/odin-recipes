# FBA 仓储与补货推演 · 飞书协作「免费版节流优化 v2.0」

**适用：3～5 人共同编辑英国、德国、法国 SKU、库存、销量、补货批次。** 保留原 HTML 的 UI 与 `EU.simulate()` 仓储费/补货计算，使用飞书多维表格作共享数据库，Node.js 单实例服务负责缓存、序列化写入及字段冲突检查。已包含英国原始 4 条 SKU 的服务器端初始化数据；首次启用才导入，升级时**不要重复导入**。

**提醒：** 这不是已经部署好的网站，必须配置自己的飞书应用、授权、部署 Node 服务。所有访问者须使用同一个 HTTPS 地址。纯上传 HTML 文件到飞书/金山云文档无法运行协作后台。

## 核心优化：为什么省 API

| 项目 | 旧版 | 免费版优化 v2.0 |
|---|---|---|
| 浏览器查看其他人在网页内的更改 | 约4秒轮询 | **约8秒轮询服务器缓存**，不直接请求飞书 |
| 服务器读取飞书三个表 | 频繁，原2.5秒缓存 | **默认每20分钟最多重新读取一次**（有用户请求时触发） |
| 提交 SKU/库存更改 | 写前读3张表，写后再读3张表 | **只写受影响的记录**；写入成功即更新共享缓存，不整表重读 |
| 多人同时写不同字段 | 按字段更新 | 按字段更新并检查期望旧值 |
| 多人同时写同一字段 | 可能后写覆盖 | **停止提交，显示冲突按钮**，自行选择保留哪方 |
| 同事直接在飞书表格改内容 | 秒级轮询 | **最长约20分钟后由服务器读取**，具体取决于活跃访问、网络及API成功率 |
| 输入框自动提交 | 0.75秒 | **1.6秒防抖**，减少碎片化写请求 |

网页右上角新增「**检查飞书更新**」。点击可以检查本服务器已缓存的数据；为节省免费额度，**距离上一次真正飞书读表不足20分钟时不会强制读飞书**，界面会提示剩余时间。若急需让网页看到直接在飞书里改的内容，请在后台下一次读表时核对；日常建议所有同事主要在网页内操作，以获取秒级协作体验。

### 3～5人的额度粗算

官方公布基础免费版企业自建应用 API 调用额度为 **每租户所有自建应用合计10,000次/自然月**，不只计算此项目（具体权益及计费是否调整请在飞书后台确认）。本项目三张表数据各少于500行且单实例：

- 工作日每天8小时、每月22天持续有人在线：`3张表 × (60÷20)次/小时 × 8小时 × 22天 ≈ 1,584 次读表/月`。
- 如果**30天全天24小时**都持续有人在线：`3 × 3 × 24 × 30 = 6,480 次读表/月`。
- **写操作另算**：每次新增/更新/删除记录通常1次 API。例如全团队每天合计20次写入、工作22天：约440次/月；因此典型工作时段的示例约为 `1,584 + 440 = 2,024 次/月`，**不是额度保证**。
- 接口分页（超过500行）、初始化、其他自建应用以及异常重试可能增加使用量。每月到飞书管理后台→费用中心→权益数据核对实际使用额度。授权 API 是否计费请以飞书官方说明为准。

官方额度说明：https://open.feishu.cn/document/platform-notices/platform-updates-/custom-app-api-call-limit

## A. 你已经用了旧版：升级步骤

1. 先用旧版网页「导出 JSON」备份现有数据；在飞书里另外保存一份多维表格备份。
2. 停止原服务（本地命令窗口 `Ctrl+C`，或暂停云平台部署）。
3. 解压 v2 项目，用新文件**覆盖旧项目源代码**；注意**保留原有 `.env`，不要用 `.env.example` 覆盖它**。更稳妥的办法是把旧 `.env` 复制到新解压目录。
4. 在 `.env` 最后增加一行 `FEISHU_REFRESH_MINUTES=20`；不设置时默认也是20分钟。
5. 在新项目文件夹执行 `npm test`，随后 `npm start`；云端部署时更新 GitHub 项目并重新部署，添加环境变量（可选）`FEISHU_REFRESH_MINUTES=20`。
6. **不要运行 `npm run seed`！** 这是首次导入脚本，不适用于已有人录入的在线数据库。
7. 两台电脑打开**相同网址**，按后面的「验收流程」检查。

同一团队只运行**一个 Node 服务实例**。这是单进程共享内存缓存，部署多个服务副本会出现缓存分叉，需要另加 Redis/分布式锁才能可靠扩容。

## B. 第一次安装：先建立飞书数据库

1. 打开飞书多维表格，创建一份**新的空白多维表格**，例如 `FBA_SKU_协作`；获取 `/base/` 后的 `app_token`。如果 URL 在知识库 Wiki 中，先打开原始多维表格地址。
2. 打开 https://open.feishu.cn/app/ ，创建「企业自建应用」，获取 App ID、App Secret，授予「多维表格查看/管理/编辑」相关读写权限并发布版本。
3. 在飞书多维表格的「更多 / 添加文档应用」中授权刚创建的应用访问该表格，否则会出现权限不足。
4. 电脑安装 Node.js **20+**；将 `.env.example` 复制为 `.env`，填入：

   ```ini
   FEISHU_APP_ID=cli_xxxxx
   FEISHU_APP_SECRET=你的飞书应用密钥
   FEISHU_APP_TOKEN=bascnxxxxx
   TEAM_PASSWORD=至少16位的随机访问口令
   FEISHU_REFRESH_MINUTES=20
   PORT=3000
   ```

   `FEISHU_TABLE_SKU`、`FEISHU_TABLE_BATCH`、`FEISHU_TABLE_SETTINGS` 此时留空。
5. 在项目文件夹打开终端，依次执行：

   ```bash
   npm run setup
   npm run seed
   npm test
   npm start
   ```

   `setup` 会创建 `FBA_SKU`、`FBA_补货批次`、`FBA_站点设置` 并写入三个 table_id；`seed` 只在**首次且三个目标表均为空**时执行；`start` 启动后台。
6. 浏览器打开 `http://localhost:3000`，输入 `TEAM_PASSWORD`。此地址只供该电脑访问。要供团队访问，需要下一节的公网 HTTPS 部署。

飞书多维表格开发文档：https://open.feishu.cn/document/server-docs/docs/bitable-v1/bitable-overview

## C. 让3～5名同事访问同一个网址

1. 把源代码存进**私有 GitHub 仓库**；不要上传 `.env`，也不要把 App Secret 或 TEAM_PASSWORD 写进公开文档。
2. 在 Render（https://dashboard.render.com/）创建 Web Service，连接仓库，Node 服务运行命令 `npm start`，构建命令 `npm install`。
3. 在 Render `Environment` 里设置与本机相同的 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_APP_TOKEN`、3个 `FEISHU_TABLE_...` ID、`TEAM_PASSWORD`，添加 `FEISHU_REFRESH_MINUTES=20` 和 `NODE_ENV=production`。
4. 部署后拿到类似 `https://xxx.onrender.com` 的 HTTPS 链接。**3～5人都访问这同一个链接**，各自输入团队口令。
5. 只开 **1 个服务实例**；免费部署服务可能休眠或平台收费政策变化，注意在部署平台核对当前方案、额度与持久在线要求。

## D. 真实使用和验收（两台电脑）

1. A电脑进入英国 → `SKU 与库存`，点击 `＋ 新增 SKU`，输入 `TEST-COLLAB-001`，按 **Enter** 或离开输入框，确认顶部出现「所有修改已写入飞书」。
2. B电脑登录**同一个网址**，保持在英国的 `SKU 与库存` 页面，通常约8秒或重新聚焦浏览器后看到新增 SKU。
3. B电脑把某一 SKU 的 `FBA可售库存` 设为 `35`，按 Enter；A电脑应显示35。检查 `仓储与补货推演`、`每日明细` 计算仍能运行。
4. 在飞书 `FBA_SKU` 表中核对英国新增的 `TEST-COLLAB-001`。再直接修改其中一个字段：**在服务器下一次真正读表后**，网页应看到变更（通常最长约20分钟，不含网络失败/休眠）。
5. A/B同时修改同一 SKU 的不同字段，应该合并；同时修改同一字段，如果两端数据有版本差异，后提交者会看到「同步冲突」：`采用云端冲突字段` 或 `使用我的内容覆盖`。选择后继续保存。
6. 打开网站左上方 `检查飞书更新`，如提示尚未到20分钟读表间隔，表示使用缓存防止消耗免费额度；这个按钮**不是绕过限额强制读取的按钮**。

## E. 请特别注意

- **在网页中改动 = 立即写飞书 + 其他网页约8秒显示；在飞书多维表格中直接改动 = 下次20分钟读表时进入网页。** 两条路径不要混淆。
- **不同字段的版本比对主要针对通过本协作网页提交的修改。** 飞书表格直接编辑发生在两次拉取之间时，后续网页修改相同字段仍可能覆盖尚未读入服务器缓存的飞书外部改动。团队尽量通过协作网页录入生产数据；从飞书直接编辑前后请协调并核对。要实现全渠道强一致，需要增加飞书事件订阅或逐记录校验，会提高复杂度及用量。
- 同一行操作有可能在网络错误时部分写入；遇到「保存失败」**不要直接关闭页面**，应先导出 JSON 并与飞书实际数据核对。
- 这是共享团队口令，尚无个人飞书 OAuth、按人审计/权限；只适用于可信的内部团队。要限制个人权限或记录谁改了库存，需另加个人登录及审计机制。
- 同一国家 SKU 名不能重复，不要在飞书里手动改 `ID`、`国家` 唯一键；数值空白代表未知，`0` 表示明确为零。
- 原仓储费模型为经营决策估算，并非 Amazon 官方结算数据；实际计费请以后台账单和费率规则为准。
- 本交付经 **12项自动测试（含模拟飞书接口 HTTP 联调）**。没有你的飞书真实租户凭证，未对真实飞书租户完成端到端上线验证。当前测试环境的浏览器访问本地网站受限，正式上线仍须按 D 节做双人浏览器验收。

运行测试：`npm test`。不要把 `.env` 发到聊天里或分享给同事。
